## 一、产品定位

### 一句话定位

**1 秒确认，安心转身** — 面向普通人的"Did I?"确认工具，不是待办，不是提醒，是"我做过了"的安心感。

### 定位三要素

| 维度 | 定义 |
|------|------|
| **品类** | "Did I?" 确认工具（Checker's Anxiety App） |
| **差异** | 不是"该做了"提醒，是"做过了吗"确认；不是 OCD 工具，是普通人日常安心工具 |
| **锚点** | 确认最快 — 比微信发自己更快，比回去看一眼更省心 |

### 目标用户

| 优先级 | 用户 | 场景 | 频次 |
|--------|------|------|------|
| 🔴 P0 | 通勤锁车族 | 每日锁电动车/自行车后确认 | 每日 1-2 次 |
| 🔴 P0 | 规律服药人群 | 每日服药后确认"吃了没" | 每日 1-3 次 |
| 🟡 P1 | 日常确认者 | 关火、锁门、喂宠物等自定义场景 | 每周 1-5 次 |

> 门口效应是所有人的正常体验——这不是病，是人脑按空间组织记忆的必然结果。

## 二、MVP 功能规格

### F1：今日确认面板（首页）

**优先级**: P0 | **平台**: 微信小程序

| 属性 | 定义 |
|------|------|
| 功能 | 首页展示所有事项的今日确认状态，一眼看到全部 |
| 输入 | 无需操作即可查看 |
| 输出 | 每个事项显示：名称 + 状态图标（✅已确认 / ⏳待确认）+ 确认时间 |
| 规则 | 每日 00:00 自动重置所有事项为"待确认" |
| 空状态 | 首次使用时显示预设模板（锁车、服药）+ "添加事项"引导 |

**关键决策**：首页是确认面板而非空列表——打开就能看到状态，接近智能硬件"看到状态"的体验，缓解"主动记录"不如"被动查看"的结构性矛盾。

### F2：确认操作

**优先级**: P0 | **平台**: 微信小程序

| 属性 | 定义 |
|------|------|
| 功能 | 对某个事项执行"已做"确认 |
| 操作方式 | 方式 A：点按钮确认（1次点击）<br>方式 B：拍照确认（1次点击 + 1次拍照） |
| 记录内容 | 事项名 + 确认时间 + 确认方式（按钮/拍照）+ 照片（如拍） |
| 覆盖规则 | 同一事项同日可多次确认，保留最近一次 |
| 反馈 | 确认后即时显示 ✅ + 时间，视觉强调"已确认"状态 |

### F3：事项管理

**优先级**: P0 | **平台**: 微信小程序

| 属性 | 定义 |
|------|------|
| 功能 | 创建、编辑、删除确认事项 |
| 预设模板 | 锁车、服药（首次使用时自动创建） |
| 自定义事项 | 用户可添加任意事项（关火、锁门、喂猫等） |
| 事项属性 | 名称 + 图标（可选，从预设图标库选择） |
| 每日次数 | **MVP 默认 1 次**；可通过事项右侧 `+` 按钮手动增加同一事项的确认槽（如服药早/晚）；表单中次数选择器为 **Post-MVP 功能** |
| 排序 | 支持拖拽排序，常用事项靠前（**Post-MVP**，MVP 手动维护顺序） |
| 数量限制 | 免费版最多 10 个事项 |

### F4：历史记录

**优先级**: P1 | **平台**: 微信小程序

| 属性 | 定义 |
|------|------|
| 功能 | 查看事项的历史确认记录 |
| 列表内容 | 日期 + 各事项确认状态 + 确认时间；照片缩略图为 **Post-MVP 功能**（MVP 显示事项图标） |
| 筛选 | 按事项筛选、按日期范围筛选 |
| 存储 | 本地存储，无需登录即可使用 |

### F5：数据存储

**优先级**: P0 | **平台**: 微信小程序

| 属性 | 定义 |
|------|------|
| 策略 | 本地优先，无需登录即可使用完整功能 |
| 存储范围 | 事项列表 + 确认记录 + 照片（小程序本地存储） |
| 登录价值 | 登录后可云同步、多设备查看（中期功能） |
| 隐私 | 照片仅存本地，不上传服务器（MVP 阶段） |

## 三、用户故事 & 操作步骤

### 用户故事

#### US1：通勤锁车确认（P0 核心场景）

**用户**：小王，26岁，骑电动车通勤，每天到公司楼下锁车后总怀疑自己没锁好

**触发**：到公司工位坐下，突然想"我锁车了吗？"

**期望结果**：打开小程序 → 看到"锁车 ✅ 08:32" → 安心，继续工作

---

#### US2：规律服药确认（P0 核心场景）

**用户**：李阿姨，58岁，高血压患者，每天早餐后服药，偶尔忘记"今天吃了吗"

**触发**：下午想起早上服药的事，不确定是否已吃

**期望结果**：打开小程序 → 看到"服药 ✅ 08:15 · 拍照" → 确认已吃，安心

---

#### US3：事后焦虑查看（P0 高频场景）

**用户**：张先生，35岁，出门旅游前关了所有电器，到机场后怀疑"我关了吗？"

**触发**：已在机场，突然想起出门前做的事

**期望结果**：打开小程序 → 看到"关火 ✅ 昨天 22:05" → 确认已关，不折返

---

#### US4：自定义事项管理（P1 场景）

**用户**：陈女士，42岁，养猫，需要确认"喂猫了吗"

**触发**：第一次使用，系统预设了锁车和服药

**期望结果**：添加"喂猫"事项 → 选猫图标 → 设每日1次 → 保存 → 今日面板显示喂猫待确认

### 详细操作步骤

#### 场景 1：首次使用（Onboarding）

```
1. 打开小程序
   ↓
2. 欢迎页：显示"告别'门口'效应" + 三步引导
   - 预设了锁车和服药，可直接开始使用
   ↓
3. 点击"开始使用"
   ↓
4. 进入今日确认面板
   - 显示预设事项：🚲 锁车 #1、💊 服药 #1
   - 状态均为 ⏳ 待确认
   ↓
5. 用户可直接确认，或添加自定义事项
```

#### 场景 2：日常确认（核心路径，~3秒完成）

```
1. 打开小程序
   ↓
2. 看到今日确认面板（首页即状态页）
   - 🚲 锁车 #2 ⏳ 待确认
   - 💊 服药 #2 ⏳ 待确认
   ↓
3. 点选"锁车 #2"卡片
   - 卡片高亮选中，底部按钮变为"拍照确认「锁车 #2」"
   ↓
4. 选择确认确认方式（二选一）：
   
   4a. 快速确认（最快路径）
       - 点击底部"快速确认"按钮
       - 卡片变为 ✅ 已确认 + 时间戳 08:32
       - 底部按钮恢复默认状态
       
   4b. 拍照确认（需证据的场景）
       - 点击底部"拍照确认"按钮
       - 调用相机拍照
       - 卡片变为 ✅ 已确认 + 时间戳 + "拍照"标记
   ↓
5. 安心离开，需要时随时回来查看
```

#### 场景 3：查看历史记录

```
1. 打开小程序 → 在今日面板
   ↓
2. 点击 Tab 切换到"历史"
   ↓
3. 按日期分组查看：
   - 昨天 · 5月26日（可折叠）
     - 08:30 锁车 · 按钮确认
     - 07:12 服药 · 拍照
   - 前天 · 5月25日（可折叠）
     - 08:45 锁车 · 按钮确认
   ↓
4. 点击某条历史记录
   - 弹出详情面板：事项名、确认时间、确认方式、照片（如有）
```

#### 场景 4：添加自定义事项

```
1. 在"添加新事项"行点击
   ↓
2. 填写表单：
   - 名称 *：输入"喂猫"
   - 图标（可选）：选择 🐱
   - （每日次数选择器为 Post-MVP，MVP 默认 1次，可后续用 + 按钮添加槽）
   ↓
3. 点击"保存"
   ↓
4. 返回今日面板，新增"🐱 喂猫 #1 ⏳ 待确认"
```

#### 场景 5：撤销确认

```
1. 点击已确认的卡片（如"锁车 #1 ✅ 08:32"）
   ↓
2. 弹出详情面板，显示确认信息
   ↓
3. 点击"撤销确认"
   ↓
4. 卡片恢复为 ⏳ 待确认状态
   - 时间戳清除
   - 排序恢复至待确认区域
```

## 四、MVP 交互规格摘要

> 详细交互设计见 [交互设计文档](../03-design/interaction-design.md)

### 核心流程

```
打开小程序 → 看到今日确认面板 → 点击事项确认（按钮/拍照）→ 看到✅安心离开
```

### 操作步骤对比

| 操作 | 过门不忘 | 微信发自己 |
|------|---------|-----------|
| 确认一件事 | 打开 → 点确认（2步，~3秒） | 打开微信 → 文件传输 → 打字/拍照 → 发送（4步，~8秒） |
| 查看确认状态 | 打开 → 一眼看面板（1步，~1秒） | 打开微信 → 翻聊天记录（3步，~5秒） |

## 五、明确不做（MVP 反目标）

| 不做 | 原因 |
|------|------|
| "该做了"提醒 | 这是吃药提醒 App 的事，我们只做"做过了吗"确认 |
| 社交/社区功能 | 纯工具，不做分享和社区 |
| 健康数据追踪 | 不做血压/血糖等健康指标记录 |
| 家人共享 | 变现突破口，但不是需求验证点 |
| 语音口喷 + AI 整理 | 中期功能，验证留存后加 |
| GPS 验证 | 中国用户隐私敏感，且小程序能力受限 |
| 云同步/多设备 | 需要登录体系，MVP 先不做 |

## 六、验证指标

| 指标 | 阈值 | 衡量什么 |
|------|------|---------|
| 次日留存 | > 40% | 产品是否有即时价值 |
| 7日留存 | > 25% | 是否有持续需求 |
| 确认频次/用户/周 | > 3次 | 是否真正在用 |
| 拍照确认占比 | > 30% | 拍照是否是核心功能 |
| NPS | > 30 | 用户是否觉得比替代方案更好 |
| 自定义事项添加率 | > 20% | 除预设场景外是否有多场景需求 |

## 七、三阶段路线图

| 阶段 | 平台 | 核心目标 | 关键功能 |
|------|------|---------|---------|
| **Phase 1** (MVP) | 微信小程序 | 验证需求是否存在 | 今日确认面板 + 拍照/按钮确认 + 自定义事项 + 历史记录 |
| **Phase 2** | 原生 App | 核心体验升级 | 锁屏 Widget + 桌面 Widget + Apple Watch + 语音确认 |
| **Phase 3** | 跨平台 | 增强与变现 | AI 拍照识别 + 家人共享 + GPS 离家提醒 + IoT 联动 |
